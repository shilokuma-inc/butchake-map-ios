# デザイン案のモック

「ぶっちゃけmap」のデザイン案を、静止画のモックで比べるための置き場です。
依頼は Issue #44「デザインを改善したい」、方針は Discussion #45 で決めました。

- 比べるのは静止画だけです。案ごとの PR に書き出した画像を添付し、それを見比べて採用する案を 1 つ選びます
- **モックはアプリに組み込みません。** 採用した案の本実装（色・フォント・アイコン・動きをアプリに入れること）は、案を選んだ後に別の依頼で行います
- 方向性は A（ポップ＆ツッコミ）と B（レトロ観光パンフ）の 2 つで、それぞれ 5 案（計 10 案）を作ります

## 書き出し方

```sh
Tools/render_design_mocks.sh a1 b1      # 案を指定する
Tools/render_design_mocks.sh --all      # 全案（と docs/design/compare/）
python3 Tools/check_design_contrast.py docs/design/mocks/a1   # 配色のコントラスト比を確かめる
```

- 書き出しは macOS の WebKit で行います（`Tools/render_design_mocks.swift` を `xcrun swift` で動かす。Google Chrome は要りません）。
  `xcode-select` が CommandLineTools を指している Mac では、`DEVELOPER_DIR=/Applications/Xcode….app/Contents/Developer` を付けて実行します
- 出力先は `build/design/<案 ID>/<ページ名>.png` です。`build/` は gitignore 済みで、**画像はコミットせず PR に添付します**
- 次のどれかがあると、書き出しは 0 以外で終わります（□ や代替フォントのまま添付しないため）
  - フォントの読み込みの失敗（`mock-fonts` に書いた書体が読み込まれていない・読み込みがエラー）
  - 画像の欠け（`<img>` を読み込めない）
  - 寸法の違い（ページの中身が `mock-size` からはみ出している・書き出した画像のピクセル数が違う）
  - ページの JavaScript のエラー・Promise のエラー（`unhandledrejection`）
  - 読み込めない CSS・スクリプト・画像
  - Web フォント（`fonts.googleapis.com`）を読み込んでいるのに `<meta name="mock-fonts">` が無いページ（Web フォントを使うページでは `mock-fonts` が必須）
  - JSON のオブジェクトとして読めない `palette.json`
  - 英小文字・数字・ハイフン・下線以外を含む案 ID
- `check_design_contrast.py` は案の `palette.json` の組ごとに WCAG のコントラスト比を出し、AA 未満（通常の文字で 4.5:1、大きな文字で 3:1）があれば 0 以外で終わります。
  出した表は PR 本文に載せます。ブランドシートには、同じ式で計算した表を `Mock.paletteTable()` で描きます
- `current` は今のアプリを写した比較の基準なので、AA 未満の組（オレンジの小さな文字など）もそのまま載せています。`check_design_contrast.py` が通らなくてよいのは `current` だけです

## ページの作り方

1 案は `docs/design/mocks/<案 ID>/` に置きます（`a1`〜`a5`・`b1`〜`b5`）。`current` を写して始めると早いです。

| ファイル | 中身 |
| --- | --- |
| `home.html` / `detail.html` / `map.html` | ホーム・投稿詳細・マップの 3 画面（402x874、3 倍で 1206x2622 px） |
| `brand.html` | ブランドシート: アプリアイコン（1024 と 60pt 相当）・ロゴ・空の状態のイラスト・カラーパレットとコントラスト比・書体見本（日本語と英語）・主な部品 |
| `motion.html` | 動きのコマ割り: 1 つの動きを 3〜4 コマに分け、時間・イージング・ハプティクス・Reduce Motion のときの代わりを注記する（3 つ以上） |
| `palette.json` | 色の見本（`colors`）と、文字色と背景色の組（`pairs`。`large` は大きな文字か） |
| `README.md` | コンセプト・「面白さ」の出し方・配色・書体（名前・ライセンス・同梱するおよそのサイズ）・アイコン／ロゴ／イラスト・動き・本実装の注意 |
| `*.svg` | 自分で描いたアイコン・ロゴ・イラスト |

ページの HTML の `<head>` に、書き出す大きさと確かめる書体を書きます:

```html
<meta name="mock-size" content="402x874">                    <!-- CSS の px。必須 -->
<meta name="mock-scale" content="3">                          <!-- 1px を何ピクセルで書き出すか。省略すると 3 -->
<meta name="mock-fonts" content="Dela Gothic One|Zen Maru Gothic">   <!-- 読み込みを確かめる書体 -->
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Dela+Gothic+One&family=Zen+Maru+Gothic:wght@500;700&display=block">
```

- ブランドシートやコマ割りのように大きなページは、`mock-size` を自由に決め、`mock-scale` を 2 にして画像を軽くします
- `html` / `body` に `overflow: hidden` を付けないでください（はみ出しを検出できなくなります）。画面の外に出すもの（カルーセルなど）は `.screen` の中で切ります
- 属性の順は `name` → `content` にします（書き出しのツールがこの順で読みます）

### 雛形（`docs/design/template/`）

| ファイル | 中身 |
| --- | --- |
| `tokens.css` | CSS 変数のトークン（色・書体・角丸・線・影・地図のイラストの色）。既定値は今のアプリの見た目。案ごとに `:root` を上書きする |
| `frame.css` | 画面の骨組み（ステータスバー・ナビゲーション・タブバー・ホームインジケーター）と、今のアプリの部品の見た目 |
| `mock-data.js` | モックデータ（`ButchakeMap/Models/MockData.swift` の投稿・スポット・カテゴリ・地元民／リピーター／旅好き と、画面の日本語の文言） |
| `icons.js` | アイコンの SVG（SF Symbols に似せて自分で描いたもの）。案ごとに `Mock.icons.<名前>` を差し替えてよい |
| `mock.js` | 組み立ての関数（`Mock.screen`・`Mock.navBar`・`Mock.tabBar`・`Mock.parts`・`Mock.mapIllustration`・`Mock.paletteTable` など） |

- 各案は雛形を読み込み、トークンと飾りを差し替えます。レイアウトも変えてかまいません
- 雛形を変えたときは、作り終えた案の書き出しが崩れないかを `Tools/render_design_mocks.sh --all` で確かめます
- `mock-data.js` の `isLiked` / `isStarred` は、いいね済み・保存済みの見た目も描けるよう、アプリのモックデータと違う値にしています。
  アプリの投稿には「タグ」の項目が無いので、カテゴリと投稿者の属性のバッジ（アプリの `TagBadge`）をタグとして描きます

## 共通の決まり

Discussion #45 で決まったこと:

- 配色は案ごとに自由（今の青 `#2B6CB0`・オレンジ `#DD6B20` に縛られない）
- フォントは無料のカスタムフォント（Google Fonts などの OFL の書体）を使ってよい。日本語の字形がある書体を使い、日本語と英語の両方で表示を確かめる
- 範囲は色・フォント・部品・画面のレイアウトに加え、アプリアイコン・ロゴ・イラストまで
- 比較の段階はライトモードだけ作る
- 動きは画面遷移や投稿の公開などにも積極的に入れる（いいねでハートが弾む・スターが光る・ボタンの軽い振動、投稿の公開時のお祝い演出、カードの出現、マップのピンが跳ねる など）。
  「視差効果を減らす」（Reduce Motion）がオンのときは動きを抑える。点滅は 1 秒に 3 回未満にする
- 採用案を 1 つに絞り、アプリ内の比較用の切り替えは作らない（比較用の案はプロトタイプの品質でよい）
- 文字と背景のコントラストは WCAG AA 以上。Dynamic Type と VoiceOver の今の対応は崩さない（採用後の本実装で守る。モックでも本文の文字は 15pt 相当以上にする）
- 色の値や細かな余白は採用後に直せるので、案の段階では仮の値でよい

作り方として仮に決めたこと（判断ログ Issue で確かめてもらう）:

- モックは HTML / CSS / SVG で描き、macOS の WebKit で PNG に書き出す（別案: SwiftUI の Preview）
- フォントは Google Fonts から `<link>` で読み込み、フォントのファイルはリポジトリに入れない（同梱は採用後の本実装で行う）
- 1 案で描くのは、ホーム・投稿詳細・マップの 3 画面、ブランドシート、動きのコマ割り
- 動きは静止画のコマ割りで見せ、動画（GIF / mp4）は作らない
- 書き出した画像はコミットせず、PR に添付する
- 端末は iPhone 17 Pro 相当（402x874pt、3 倍で 1206x2622px）。ステータスバーとホームインジケーターも描く

そのほかの注意:

- 今のアプリの機能・情報を落とさない（5 つのタブ、投稿の「マイ三大」（スポット 3 つと順位）・タイトル・カテゴリ・地元民／旅人・都道府県・いいね・スター・作者、
  マップのピン、投稿詳細のシェアカード・外部の地図で開く）。モックで省いた情報は案の README に書く
- 地図は実際の地図の画像を使わず、イラストで描く（`Mock.mapIllustration`）。画像やアイコンを外部のサイトから取ってこない（SVG は自分で描く）
- 添付した画像は消せない public の添付になります。実在の個人の情報・トークンを写さないでください

## Before（今のアプリ）

PR の Before には、今のアプリを Simulator で撮った画像（ホーム・投稿詳細・マップ）を使います。
アプリの撮影モード（`-screenshot-demo -screenshot-scene home`）で開いたデモデータの画面です。
投稿詳細とマップは、撮影のときだけ一時的に撮影モードの画面を足して撮りました（その変更はコミットしていません）。
